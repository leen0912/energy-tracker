# 主动记录范围确认

日期：2026-09-16。状态：用户已确认的需求边界；用户后续授权开发，本轮已实现。部署与验证见 [交付记录](RELEASE-20260916.md)。

## 首版只响应主动记录

用户决定：先让用户记录，催促与提醒留待后续版本。

- 读取当前设备本地时间，作为记录的默认发生时间；允许改为实际发生时间并补记。
- 时间用于当天归档、日历回看、呈现实际用餐或饮用时刻。未知时间不伪装成精确事实。
- 不根据当前时间弹出“该吃饭了”“午饭有着落了吗”等提示，包括应用内提示。
- 不显示漏餐、逾期、红点或倒计时，不根据没有记录推断没有吃饭，不自动扣电。
- 不做订阅消息、后台提醒、闹钟、定时通知或“稍后提醒”，不为以后功能预先请求相关授权。
- 记录后的数字变化、花园生长与“已记下”是即时操作反馈，保留；不把它们变成反复催促。

## 主动记录的内容

用户主动打开进食入口后，可以记录吃了、还没吃、吃饱了或吃得满足。是否吃过、实际时间、饱腹感、情绪感受是不同维度，不设为互斥的单一选项，也不要求逐项填写。

“还没吃”是一条当时的状态；随后记录吃饭，不自动重复形成一笔消耗或清空已有经历。首版不据此建立提醒任务。

咖啡、奶茶、补剂提供主动记录入口：默认记名称与时间，份量等为可选内容。饮用或服用事实不自动换成恢复分数。用户自愿补充实际感受时，才区分补充或消耗；只是记录也能进入花园。

首次用“现在感受怎么样？”建立起点，采用感受选项，不要求选择具体数字。日常影响大小也用可选的感受描述表达，默认记录不展示单次分值。首次选择是建立记录基础，不属于定时提醒。

## 对前面讨论的修正

此前“到饭点询问”“晚点提醒”“按个人作息调整提醒范围”等都移出首版。没有这些设置，也不留占位按钮。

旧 PRD 中默认 100 点起步、首页显示具体收支、数字档位选择已移除。感受到内部起点的试用参数、中性事件结构与补记校准边界已在 [当前 PRD](../PRD.md) 中统一，并覆盖自动化测试。旧有数据保留历史起点，不静默重写。

## 验收边界

- 在任何饭点打开应用，不会出现用餐催促或漏餐判断。
- 不记录一天，也不自动增加消耗、生成提醒或改变已保存事实。
- 用户主动记录时默认填入当前本地时间，可修改时间，保存后按实际日期归档。
- 进食、饮用、补剂及陪伴的记录不要求用户填写点数或完成问卷。
- 本轮增加用户主动填写的用餐详情、饮品/补剂份量与减少动效偏好；不新增敏感权限。相册写入、剪贴板写入的既有用途保留。

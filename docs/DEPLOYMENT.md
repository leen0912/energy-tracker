# 启动与部署说明

## 在电脑上开发

安装 Node.js 24 并获取仓库，在项目目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的 Local 地址。默认通常使用 5173 端口；被占用时以实际输出为准。

需要指定其他端口：

```sh
npm run dev -- --port 5174
```

## 在同一网络的手机上预览

开发服务器已经配置为允许同网访问。让 iPhone 连接电脑所在路由器的 Wi-Fi，在 Safari 打开终端显示的 Network 地址，例如 `http://电脑的局域网IP:5173`。

电脑需要保持运行。手机不能使用 `localhost` 访问电脑；访客网络隔离、VPN 或防火墙可能影响连接。不要关闭整个防火墙，必要时仅允许开发服务器在可信的私人网络上访问。

这一步用于预览页面；正式安装与离线体验使用 HTTPS 生产站点验证。

## 构建并验证

首次准备浏览器测试环境：

```sh
npx playwright install chromium
```

Linux 可改为 `npx playwright install --with-deps chromium`。然后执行：

```sh
npm run build
npm test
npm run check:pwa
```

`build` 执行类型检查与静态构建；`test` 覆盖保存、修改、删除、示例隔离、日历导入、改期、时区、备份校验、手机布局与图片生成；`check:pwa` 临时使用 4187 端口检查生产缓存和断网刷新，结束后关闭临时服务。

常规生产预览：

```sh
npm run preview
```

首次加载并完成缓存后，离线打开基础功能。开发服务器本身不启用生产 Service Worker。

## 发布静态网站

仓库上传只是保存代码，不等于网站已经发布。托管平台连接仓库后，配置如下：

| 配置项 | 值 |
| --- | --- |
| Node.js | 24 |
| 安装命令 | `npm ci` |
| 构建命令 | `npm run build` |
| 发布目录 | `dist` |
| 业务后端 | 无 |
| 应用环境变量 | 当前无必填项 |
| 网站协议 | HTTPS |
| 网站路径 | 站点根路径 `/` |

当前图标、启动地址和 Service Worker 按根路径配置。不能未经调整就放在 GitHub Pages 的 `/仓库名/` 子路径下；如采用子路径托管，需要同步修改资源路径、应用清单与缓存作用域。

项目没有绑定托管平台，也没有提交自动发布配置。可使用托管平台提供的默认网址；是否需要个人域名可在正式发布时决定。

## 手机上线验收

1. 在两人的 iPhone Safari 上打开正式 HTTPS 地址。
2. 在分享菜单中添加到主屏幕，验证图标与独立窗口。
3. 分别写入测试记录，刷新、关闭重开，确认记录保留。
4. 完成首次资源缓存后断网，验证打开日历及生成图片。
5. 验证保存 PNG、系统分享和隐私显示选项。
6. 导出并恢复一份测试备份，再导入各自实际使用的日历文件。

以上真实 iPhone 验收尚未完成。Apple Watch 原生应用和健康数据接入属于后续开发范围。

## 维护记录

发布新版本时需要重新构建并部署完整 `dist/`。应用检测到更新会提示关闭所有日迹窗口后重开。更新前后保持存储格式兼容；未来修改数据结构时应添加版本迁移。

首次正式上线前，原本局域网地址下的记录需导出备份，再到正式网址恢复。服务器不会自动收集或迁移浏览器里的个人记录。

# 个人电量显示器 PRD

版本：v0.5 主动记录优先 / 提醒后置 · 更新：2026-09-16

产品暂沿用「日迹」名称，仓库为 `energy-tracker`。下文评分与交互仍需实际试用验证；现已在 `miniprogram/` 实现首轮本地微信小程序，原网页日历原型保持独立。实现范围见第 7 节，导入与验收见 [小程序说明](./docs/MINIPROGRAM.md)。历史讨论保存在 [旧 PRD](./docs/PRD-ARCHIVE.md)。

最新范围决定：首版以主动记录为主，时间仅用于记录、补记与归档，不触发饭点提示、催促或通知。详见 [主动记录范围确认](./docs/RECORDING-FIRST.md)。这是需求确认，尚未修改程序；此前提出的提醒方案留待后续版本。

## 1. 这次调整的核心

用户提出的直觉模型是：睡眠时长、进食、弟弟带来的安慰构成充电；工作任务、人际支出、说不清的琐事构成放电，最后形成一个可以回看的比值。

产品目标改为：**让用户看见自己的精力正在怎样被消耗，又被什么补回来。**

打开应用，应能很快回答：我现在大概还有多少电？今天的电花在哪里？哪些事情确实让我恢复了一点？

它延续了番茄钟里“投入之后需要恢复”的节奏。时间依然是重要线索，但同样一小时可能让人疲惫，也可能让人满足，因此时长不能直接等于耗电量。

## 2. 用户价值与优先级

| 层级 | 要解决的问题 | 产品回应 |
| --- | --- | --- |
| 首要 | 今天为什么这么累，接下来还撑得住吗？ | 当前电量、最近充放电事件、随时校准感受 |
| 首要 | 我做了什么来补充自己？ | 个人充电项、充放电收支、恢复来源 |
| 延续 | 我最近原来消耗了这么多，也得到过安慰 | 电量日历、趋势和可收藏的总结图 |
| 延续 | 不想为了记录而进行大量设置 | 常用项一触记录、原因可空、时长可空、可补记 |

分享仍然是持续使用的动机之一，内容重点从“完成了多少”转为“我怎样度过、怎样恢复”。低电量也值得记录，不设满电排行榜或连续打卡惩罚。

## 3. 充电与放电事件

充放电方向与事件分类分开保存。快捷项有建议方向，用户可以调整；不对某项活动或某个人下固定结论。

| 常用项 | 默认方向 | 最轻输入 | 可选补充 |
| --- | --- | --- | --- |
| 睡了一觉 | 充电 | 记睡眠时长，可顺手选恢复感受 | 起止时间、睡眠质量、数据来源 |
| 好好吃了一顿 | 充电 | 点一次 | 餐次、恢复程度 |
| 弟弟充电 | 充电 | 点一次，允许不填时长 | 陪伴、抱抱、安慰、一句话 |
| 休息、散步、喜欢的事 | 充电 | 点常用项 | 实际感受，也可以改为放电 |
| 工作任务 | 放电 | 点一次或结束开放计时 | 任务名、强度、时长 |
| 人际支出 | 放电 | 点一次 | 自愿补充原因，可改为充电 |
| 莫名其妙掉电 | 放电 | 点一次，无需解释 | 后来想起来再补充 |
| 自定义项 | 用户选择 | 起个自己认识的名字 | 默认方向和影响程度 |

「弟弟」是用户的猫，也是用户自己的充电来源。界面保留这个有感情的名字；梁姐可以设置自己的常用项，不强制每个人采用同一份充电清单。

同一件事可以让人既开心又累。首版可分别补一条充电和一条放电，允许关联到同一活动；不要求用户记录这种细分。咖啡先作为背景记录，默认不自动兑换成恢复点数。

### 记录负担

- 默认动作：点「充一下」或「掉了点电」，选一个常用项，即完成记录。
- 快捷项使用预设的普通影响程度，记录后可直接改小、改大或撤销，不弹出必填问卷。
- 原因、备注、时长都是可选项；睡眠时长可补录，不能因缺失而阻止记下一次恢复。
- 补记应能选择发生时间。误触可撤销，同一日历片段不能因重复导入被重复计分。
- 不要求为零碎活动开计时器，也不要求在记录前完成个性化设置。

## 4. 电量与比值怎么计算

### 4.1 两个读数，分别回答两个问题

**当前电量（记账点数，允许透支）**回答“我现在大概还有多少余量”。它由最近一次主观校准和之后的已评估事件推算，页面明确区分「我刚刚的感受」与「根据记录估算」。

**今日补回比（充电 ÷ 放电）**回答“今天记录到的恢复，补回了多少记录到的消耗”。它是个人收支指标，不能当作身体剩余电量或健康结论。

用户不想校准时，从默认 100 点开始记账，清楚标明这不是身体测量，不创建虚假的主观校准记录。没有校准的旧记录也从这一记账起点重算；已有校准仍以最近一次校准为准。

### 4.2 首轮试用的计分草案

先使用相同的主观影响档位，便于解释和修改：小幅 5 点、普通 10 点、明显 20 点。充电为正，放电为负。**这些是界面试用参数，不是经过验证的身体换算公式。**

睡眠时长先保存为事实，实际恢复程度决定这次充电的影响档位。不采用“睡一小时必然恢复多少电”“吃一顿固定恢复多少体力”的生理假设。首版快捷项的普通点数是一项可修改的记账默认值。

相同时长的两次工作可以有不同点数，几分钟的突发烦心事也可能比长时间工作更耗电。首次试用不按时长无限线性累加，不要求用户先调权重。

### 4.3 当前电量

用户可以直接调整电池读数，记录当下主观电量 `B0` 及校准时间。校准后，按事件发生顺序更新：

```text
充电事件：B下一步 = min(100, B当前 + 本次影响点数)
放电事件：B下一步 = B当前 - 本次影响点数
```

只计算校准之后、未被这次校准覆盖的事件。例如醒来时校准的电量已经包含昨晚睡眠的结果，不能再把同一段睡眠加上一次。跨过校准时点的长事件只计之后部分；无法区分时先不自动计入。

低于零后展示「透支 X 点」，电池图形保持空格状态，但数字继续响应记录。恢复会先减少透支，例如 -20 + 10 = -10；不额外制造惩罚或自动利息。当前电量统一用「点」而非身体百分比表达。

用户随时可以说“其实我现在更累”并校准。校准是新的主观观测，不伪装成一笔充电或放电，也不抹去此前事件。

没有记录时不按时钟持续扣电。超过一天没有主观校准时，首轮方案改为突出上次记录的时间，并邀请用户确认当前感受，而不是继续展示一个仿佛实时测得的准确电量。

### 4.4 今日补回比

```text
C = 今天已评估的充电点数之和
D = 今天已评估的放电点数绝对值之和
补回比 R = C / D × 100%   （D > 0 时）
净收支 N = C - D
```

| 情况 | 显示方式 |
| --- | --- |
| C = 30，D = 50 | 补回 60%，净支出 20 点 |
| C = 40，D = 40 | 补回 100%，记录中的充放电持平 |
| C = 60，D = 40 | 补回 150%，记录中的充电多于放电 |
| C > 0，D = 0 | 已记录充电，暂无放电；不显示无限大 |
| C = 0，D > 0 | 尚未记录充电，补回 0%；不推断现实中完全没有休息 |
| C = 0，D = 0 | 暂无可计算的记录，不显示 0% |

首页同时显示 C 和 D，让用户理解比值从哪里来。150% 不意味着身体超额满电；低记录覆盖率也不能被解释成高恢复质量。

### 4.5 日期、边界与重复计算

- 日收支按设备本地日期归档；主睡眠归入醒来的日期，避免跨午夜重复加分。
- 当前电量不在零点自动恢复到 100。主观校准可以跨日延续，必须显示观测时间与估算状态。
- 当前电量保留 100 点上限，但不设零点下限；被上限截去的点数不会存成未来可用的隐形电量。已有记录、校准和备份格式保持不变，更新只改变派生读数的计算。
- 充放电原始账目不随电池上限截断。满电后仍能记录一次愉快陪伴，其含义是主观恢复记录。
- 删除、撤销、修改事件后，按有效事件和校准记录重新计算。
- 日历安排、计时结果和手表数据都是记录来源，同一段活动经确认后只记一次分。导入日历本身不扣电，全天工作日程也不自动算成连续耗电。

## 5. 一天的体验示例

以下数字只演示记账逻辑：

1. 早上，记录昨晚睡了 7 小时、恢复明显，记充电 20 点；随后把醒来时的主观电量校准为 45。
2. 一项工作让人很累，记放电 20 点；当前估计 25。
3. 好好吃了午饭，记充电 10 点；当前估计 35。
4. 一次人际支出，记放电 10 点；当前估计 25。
5. 弟弟过来陪了一会儿，点「弟弟充电」，记充电 10 点；当前估计 35。
6. 临时琐事又消耗了 10 点；当前估计 25。

今日充电 40、放电 40，补回比 100%。当前仍是约 25，因为它以早上的 45 为校准起点，睡眠已经在起点中体现，不能重复加分。这个例子正说明“今天收支持平”与“现在很有精神”是不同的事。

可以生成一张图：今天的电量变化、工作与琐事的支出、睡眠和午饭的恢复，以及一条“弟弟给我充了点电”。默认展示每条事件名称（包括猫的名字），备注始终隐藏；用户可以关闭「展示我的记录」切换为匿名收支。分享前以预览为准，标题中包含的个人信息也会随名称显示。

## 6. 页面与番茄钟的关系

### 首页：我的电量

上方显示当前电量、最近校准时间和状态；中间展示今日充电、放电、补回比；主要动作是「充一下」「掉了点电」和快捷项；下方是最近事件及可选的开始做事入口。

尚无记录时，用户可以直接记录一件事，或告诉应用当下感觉，不需填写目标专注时长。

### 电量改变页面气候

当前电量不只改变数字，也会轻微改变首页的文案、色彩重心、花园姿态、动效速度和动作排序。页面结构与导航保持稳定，避免用户在低电量时还要重新理解界面。以下分段是首轮视觉规则，不是健康判断，也不代表真实身体测量：

| 状态 | 暂定范围 | 首页主文案示例 | 界面与动作变化 |
| --- | --- | --- | --- |
| 余量充足 | 70-100 点 | 「今天，还有些余量。」 | 花朵舒展、酒红和矿物蓝稍明亮；动效轻快但不庆祝，不鼓励把余量全部用完；常用记录保持原顺序。 |
| 平稳 | 40-69 点 | 「今天，还在自己的节奏里。」 | 使用默认「都市暮色」配色与动效；充电、放电入口权重相同。 |
| 低电量 | 1-39 点 | 「今天已经消耗不少。」 | 增加留白、降低非必要动效，暖色恢复来源更突出；「充一下」和睡眠、进食、晒太阳、弟弟陪伴等快捷项前置，工作计时入口降级但不消失。 |
| 透支 | 0 点及以下 | 「今天正在透支 X 点。」 | 不使用红色警报、闪烁或枯萎画面；花园转为安静的傍晚气候，动作以「记下一次恢复」和「重新校准感受」为主。 |

高电量不等于应该完成更多，低电量也不等于今天失败。状态变化只帮助用户理解自己，并让更合适的记录入口靠前，不锁定功能、不制造任务建议和绩效压力。

文案遵循事实陈述、允许休息、不替用户下结论的原则。避免「电量告急」「只剩」「继续坚持」「今天状态很差」「再完成一点」等警报式或鸡血式表达；优先使用「今天已经走到这里了」「可以先补一点」「恢复也算今天的一部分」「忙碌有迹，恢复也有」等语言。

### 花园只会生长

花园表达「今天发生过什么」，电量表达「此刻还有多少余量」，两者不能混为奖惩系统：

- 每天从一株小苗开始，而不是从惩罚性的空白开始。
- 每记录一件生活，花园增加一种形态；记录不会让已有植物消失。
- 充电事件可以长出珊瑚或酒红花朵、柔和新叶；照顾自己可以长出古铜黄种荚或果实。
- 放电事件同样贡献植物，表现为矿物蓝小花、深色叶片、枝条或种荚，不使用枯萎、折断和掉落表达。
- 「弟弟充电」带来暖焦糖色猫咪或尾巴弧线。猫是重要的恢复来源和情绪主角，不作为卡通吉祥物或装饰贴纸。
- 电量可以下降和透支，花园仍会因为记录越来越丰富。低电量的一天也可以拥有很盛大的花园。

动效逻辑留待开发阶段实现：茎伸长、叶片展开、花苞开放和猫咪安顿应当短促、柔和，可被系统减少动态设置关闭；本阶段只确认视觉与语义。

### 已确认视觉基线

整体采用成熟的纸上花园与版画质感，主配色定为「都市暮色」：珍珠灰白背景、墨蓝文字、石油绿交互与叶片、酒红主花、古铜黄和矿物蓝点缀、暖焦糖色猫咪。保留少量更明亮的珊瑚红，用于新花出现的瞬间，避免画面过于秋冬和沉静。

### 开放式计时：一种记账入口

点击开始，后台记时，用户主动结束后形成一段候选事件。结束时可接受工作默认影响档位，也可改成充电、无影响或暂不计分。持续时长不能自动制造一笔已确认支出。

标准 25 分钟番茄节奏保留为以后可选的模式。首版重点是开始容易、结束后能感知消耗，以及自然接上一次恢复记录。

### 回看：电量日历与分享图

日历从首页移为回看入口。按日查看充电、放电、主观低电量时刻及恢复来源；空白日期显示没有记录，不判作失败。

分享图以每条日常记录为主角，默认公开名称、保留匿名开关；正文从 18 增至 28 画布像素，每张六条，更多记录分页保存，长标题最多两行并省略超长部分；保留数字来自个人记录的语义，不做健康评分或好友比较。

| 阶段 | 范围 | 当前状态 |

| 产品讨论 | 确认电量含义、点数规则、录入负担与分享重点 | 本文为讨论稿 |

| 番茄钟延伸 | 开放计时，结束后确认影响，可接恢复记录 | 小程序已本地实现；不计分时丢弃该次计时，不保留零分记录 |
| 生活回看 | 日历、图片导出、充放电记录与趋势 | 小程序已有逐日收支和每日图片；月度图片、校准趋势待做 |
| 自动采集 | 日历实时授权、睡眠来源、跨设备同步、提醒和 Watch 入口 | 后续评估 |

首轮改为微信原生小程序与本机存储方案，用两人的实际体验验证模型。先观察“记录是否轻松、数字是否符合感受、有没有帮助发现充电来源”，再讨论个人权重和自动学习。已完成本地逻辑测试和微信模板/样式编译检查，尚未完成微信模拟器或 iPhone 验收，也未上传发布。

首版仅将确认后的事件按发生时间记账，睡眠时长是可选事实，不自动拆分跨校准时段；补记睡眠时应选择实际醒来时间。日历导入、Watch 数据与长事件分段计分尚未接入。两人各自保存本机记录，不自动共享；不需要提前配置域名或后端。

## 8. 对现有模块的影响

- 保留日历导入、图片生成、备份恢复与 PWA 基础。
- 新增能量事件：编号、发生时间、来源、充放电方向、影响档位、实际点数、是否已确认，以及可选日程关联；同一来源需要稳定标识以去重。
- 新增校准记录：时间、主观电量、被覆盖的事件范围。评分规则保存版本，事件保存当时点数，调整默认权重不静默改变历史。
- 新增独立的计算模块，统一处理上限、缺失记录、零分母、撤销重算和日期归属；界面不各自计算。
- 后续增加数据版本迁移。原来的低/中/高感受保留原意，不擅自改成精确电量；旧日历也不批量兑换为能量点。
- 小程序采用独立的分享模板与三视图导航；网页保持原状，原结构见 [模块说明](./docs/ARCHITECTURE.md)，小程序模块见 [小程序说明](./docs/MINIPROGRAM.md)。

## 9. 验收与待讨论项

首轮验收关注：一次常见充放电可用两次点击完成；「莫名其妙掉电」不需要原因；手动校准立即生效；睡眠不重复计分；撤销后所有读数一致；无记录、仅充电、仅放电均有清楚的显示；分享默认展示事件名称、可切换匿名模式，备注不会进入图片。

试用时重点记录三件事：哪些默认点数经常被改，哪些活动忘了记，以及估计电量与主观感受差得有多远。首轮不以“补回比越高越好”衡量成功。

还需要一起决定：

1. 当前暂按默认 100 点起步、可透支的电池设计。试用时观察起点是否合适，以及透支反馈是否让记录更有回应。
2. 「弟弟充电」每次直接记普通影响是否顺手，还是更想只留一个充电标记、晚上再回顾？
3. 分享图更想突出一天的充放电轨迹，还是“今天是谁、什么事给我充了电”？两者都保留，但视觉主角需要试稿后决定。

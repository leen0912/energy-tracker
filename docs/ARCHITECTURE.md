# 模块与数据说明

## 技术结构

日迹是使用 Vite 构建的 TypeScript 网页应用，直接操作页面 DOM。目前没有业务后端、云数据库或登录服务。生产构建输出静态文件，PWA 插件生成安装清单和 Service Worker。

主要依赖：ICAL.js 负责 iCalendar 解析与重复日程展开，Lucide 提供图标，Canvas 绘制分享图片。依赖版本由 `package-lock.json` 固定。

## 模块边界

| 模块 | 职责 | 主要输入与输出 |
| --- | --- | --- |
| `src/model.ts` | 类型、日期、分类、按日取日程、统计、隔离的示例数据 | `Data`、日期 → 日程列表与统计 |
| `src/storage.ts` | 读取、保存、备份校验、合并恢复 | JSON ↔ 经过校验的 `Data` |
| `src/calendar.ts` | ICS 解析、时区检查、重复日程和例外处理 | 日历文本 → 待确认日程、跳过数量、提示 |
| `src/share.ts` | 日/月画布、显示选项、PNG 生成与下载 | 数据、日期、分享选项 → Canvas / PNG |
| `src/main.ts` | 页面导航、表单、导入预览、用户操作与状态协调 | 用户操作 → 模块调用与页面更新 |
| `src/styles.css` | 桌面与手机布局、组件状态 | 响应式页面样式 |
| `vite.config.js` | 构建、PWA 清单、生产静态资源缓存 | 源代码 → `dist/` |
| `scripts/verify-pwa.mjs` | 临时启动生产预览，验证缓存、断网刷新和记录保留 | 已构建的 `dist/` → 检查结果 |

## 数据结构

浏览器使用 `daytrace.data.v1` 保存一份版本化 JSON：

```ts
type Data = {
  version: 1;
  entries: Entry[];
  days: Record<string, Day>;
};
```

`Entry` 包含唯一编号、标题、开始与结束时间、分类、全天标记，以及 `manual` 或 `calendar` 来源。分类为工作、生活、休息、运动、相聚和其他。开始与结束时间存为 ISO 时间字符串。

`Day` 按设备本地的 `YYYY-MM-DD` 组织，包含可选的主观精力、睡眠简记、餐次、咖啡记录和心情。精力只有主观状态，不通过睡眠或咖啡计算健康分数。

示例数据保存在独立的内存状态中，体验示例时的修改不会写入真实记录；导出的示例图片带有标记。

## 主要流程

1. 打开应用：读取本地 JSON，校验后渲染日历、当天记录和图片预览。
2. 日常记录：操作表单或状态按钮，保存成功后更新页面；感受输入即时保存。
3. 日历导入：读取用户选择的 ICS 文件，解析并预览分类，用户确认后按唯一编号合并。
4. 图片分享：根据选定日期和显示选项在本机绘制画布，导出 PNG，设备支持时调用系统分享。
5. 备份恢复：先校验文件，再让用户确认合并；同编号日程与同日感受优先保留当前版本。

## 日历规则

- 导入范围为当前月及前后各六个月，不提供实时日历同步。
- 单次日程按 UID 保持身份，改期后再导入会更新同一段日程；重复日程使用 UID 与发生时间标识。
- 处理重复规则、排除日期及改期例外；缺少时区定义的日程跳过并提示。
- 总时长按本地日期切分跨日事件，并合并重叠时段；全天事项不算作 24 小时。
- 日历中的安排不自动认定为已完成。
- 原日历删除或取消的旧记录不会在日迹中自动清除，需要手动移除。

## 已知边界

- 同一网址在不同浏览器、不同设备上保存不同数据；改用新网址也需要导出和恢复备份。
- 清理站点数据可能移除记录；存储失败时显示提示，读取损坏数据时保留原始内容以供导出。
- 输入与导入文件只在本机处理。精力、日程标题和心情原文默认不进入分享图片。
- 饭点提示只在页面内显示。尚无后台定时推送、AI 聊天、Google OAuth、Apple Health 或 Watch 原生模块。
- 页面与操作当前集中在 `main.ts`。后续界面明显扩大时，可按日历、分享、设置分离页面组件；数据和导入模块可继续复用。
